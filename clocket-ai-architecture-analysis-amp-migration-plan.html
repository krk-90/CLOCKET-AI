Codebase inspection of CLOCKET-AI / Personal Assistant · Transformation roadmap to Clocket AI

F · Database Changes

New table: repositories

id            uuid  PK default gen_random_uuid()
user_id       uuid  FK auth.users  (RLS owner)
github_url    text  NOT NULL
owner         text  NOT NULL
name          text  NOT NULL
default_branch text NOT NULL default 'main'
commit_sha    text
status        text  default 'pending'  -- pending|analyzing|ready|failed
created_at    timestamptz default now()
updated_at    timestamptz default now()
UNIQUE (user_id, github_url)

G · MCP Changes

MCPActionUsed for
mcp-server-gitKEEPGit chat agent — git status, diff, log, branches
Task MCP (mcp_server/tools.py)KEEPGeneral task manager, onboarding task status updates
GitHub MCP Server (official)ADDRepository info, tree, file content, code search, commits, PRs
Clocket AI MCP (mcp_server/clocket_ai_tools.py)ADDsave_repository_analysis, get_onboarding_progress, update_onboarding_task, analyze_repository trigger
GitHub MCP usage: The official github/github-mcp-server Docker image is used via MultiServerMCPClient (same pattern as mcp-server-git). It provides: get_repository, get_file_contents, get_tree, search_code, list_commits, list_branches, list_pull_requests. No custom tool is built for functionality already in GitHub MCP.

Clocket AI-specific MCP tools (new)

  • analyze_repository(github_url, user_id) — trigger full pipeline
  • save_repository_analysis(repository_id, analysis_json) — persist structured analysis
  • get_onboarding_progress(user_id, repository_id) — return task completion state
  • update_onboarding_task(task_id, user_id, status, notes) — mark task progress

H · LangGraph Onboarding Workflow

State: OnboardingState {
  github_url, user_id, repository_id,
  repo_info, file_tree, important_files,
  technology_stack, architecture,
  dependencies, configuration, apis, database_info,
  setup_guide, setup_issues, onboarding_plan,
  starter_tasks, rag_indexed, error, status
}

START
  ↓
validate_github_url      ← pure Python, no LLM
  ↓
get_repository_info      ← GitHub MCP: get_repository
  ↓
read_repository_tree     ← GitHub MCP: get_tree (recursive, limited depth)
  ↓
detect_technology_stack  ← static scanner (deterministic, file extensions + filenames)
  ↓
analyze_important_files  ← GitHub MCP: get_file_contents for README, package.json,
                            requirements.txt, Dockerfile, .env.example, etc.
  ↓
analyze_dependencies     ← static scanner (parse package.json, requirements.txt,
                            pyproject.toml, pom.xml, go.mod, etc.)
  ↓
analyze_configuration    ← static scanner (.env.example, config files, render.yaml)
  ↓
analyze_apis             ← LLM reasoning over route files
  ↓
analyze_database         ← static scanner + LLM (*.sql, ORM models, connection strings)
  ↓
analyze_architecture     ← LLM: produces structured JSON architecture
  ↓
index_into_rag           ← SupabaseRetriever extended with repository_id
  ↓
generate_setup_guide     ← LLM: evidence-only from analyzed files
  ↓
generate_onboarding_plan ← LLM: personalized plan
  ↓
generate_starter_tasks   ← LLM: grounded tasks with real file references
  ↓
persist_results          ← Supabase insert/upsert
  ↓
END

Error handling: each node catches exceptions, sets state.error,
conditional edges skip to persist_results on failure.

I · Implementation Phases

Phase 1 — Database SQL only, no code risk

Create supabase/repositories.sql, supabase/analysis.sql, supabase/onboarding.sql. Extend supabase/rag.sql with new columns, updated RPC. All idempotent.

Phase 2 — Backend Routes New files only

Add app/routes/repositories.py, app/routes/analysis.py, app/routes/onboarding.py. Register in app/main.py. Existing routes untouched.

Phase 3 — Clocket AI MCP + GitHub MCP New file + minimal existing change

Add mcp_server/clocket_ai_tools.py. Add mcp_server/server/github_server.py (GitHub MCP adapter). Keep mcp_server/tools.py unchanged.

Phase 4 — Analysis Agents New module: agent/analysis/

Build agent/analysis/scanner.py (deterministic), agent/analysis/architecture.py, agent/analysis/setup_guide.py, agent/analysis/task_generator.py.

Phase 5 — LangGraph Onboarding Workflow New module: agent/graph/onboarding/

Build agent/graph/onboarding/workflow.py (15-node StateGraph). Integrate GitHub MCP, static scanner, RAG indexer. Wire to analysis route.

Phase 6 — RAG Enhancements Minimal change to existing RAG files

Extend agent/rag/retriever/retrieval.py SupabaseRetriever to accept + filter by repository_id. Extend agent/rag/loading.py supported suffixes. Update generation.py source citations.

Phase 7 — Frontend Dashboard Largest visible change

Replace app/frontend/src/main.jsx with multi-page React app (react-router-dom). 9 pages: Login, Dashboard, Add Repo, Repo Overview, Architecture, Setup Guide, Starter Tasks, Q&A, Progress. Professional hackathon UI.

Phase 8 — Config + Docs Low risk

Update .env.example, render.yaml, Dockerfile (add GitHub MCP Docker image pull). Write new README.md with all 13 required hackathon sections.

Phase 9 — Validation Final gate

Run pytest, fix imports, verify frontend build (npm run build), verify API endpoints, verify Docker build, verify RAG filtering, manual smoke test of full onboarding pipeline.

Zero-regression guarantee: All existing routes (/auth, /chat, /rag, /health) and their underlying agents remain completely functional. New features are additive only. The existing chat experience is preserved alongside the new Clocket AI features.
